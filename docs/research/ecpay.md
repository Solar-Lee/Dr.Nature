# ECPay 綠界串接查證（P4-01）

> 2026-10-13：3 個研究代理只用官方來源（developers.ecpay.com.tw、www.ecpay.com.tw、github.com/ECPay）整理，再由獨立查核代理逐條回到官方頁面嘗試推翻。結果：50 條中 **40 條確認、10 條更正**（更正內容已列在「查核結果」欄，以更正為準）。「未驗證」清單中的項目不可當事實，需在測試環境實測。

> 文中出現的 MerchantID／HashKey／HashIV 只限 ECPay **官方公開的測試環境值**；正式金鑰依 CLAUDE.md 只寫在主機環境變數。

## 實作要點（由下方查證整理）

1. **金額**：`TotalAmount` 必須是整數新台幣，不可有小數 → ECPay provider 收到非整數金額直接拒絕（與 docs/research/medusa-p3.md 第 3 點一致）。
2. **CheckMacValue**：參數依名稱排序 → 前加 `HashKey=…&`、後加 `&HashIV=…` → .NET 風格 URL encode → 全部小寫 → SHA256 → 轉大寫。以官方範例（CMV-03）與 ECPay-API-Skill 的 test-vectors 當單元測試（P4-02）。**所有回呼都必須驗章**。
3. **ReturnURL 是付款結果的唯一依據**（伺服器對伺服器，須回 `1|OK`）；OrderResultURL 是瀏覽器導回，可能不會到。`SimulatePaid=1` 一律視為未付款。
4. **網路**：回呼網址只用 HTTPS 443、合法網域；正式環境需允許 postgate.ecpay.com.tw 進站。
5. **物流與發票的金鑰**：測試環境與金流不同組；正式環境是否共用官方未明說 → 設計上三組獨立設定（docs/ENV.md 已分開）。
6. **電子發票**：AES-CBC 加密 JSON（URL encode 後加密、base64），用 Python/PHP 官方 SDK 的編碼行為當參考；ECPay 沒有官方 Node.js SDK，需自行實作並以測試環境驗證。
